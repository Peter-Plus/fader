# Fader · 网站直连

Chrome Manifest V3 扩展，支持配合提供本地 HTTP 或混合代理端口的常见代理软件使用，不限于 Clash。打开网页，点击「fade」让当前域名直连并刷新，点击「allow」恢复代理。右上角设置管理端口和直连规则。没有远程服务、统计或依赖。

## 代理软件兼容性

- 不依赖特定代理客户端或其专属接口。代理软件提供本地 HTTP 或混合代理端口时，在设置中填写对应端口即可使用；手动设置连接的是 `127.0.0.1`，不能填写仅支持 SOCKS 的端口。
- 如果 Chrome 提供可读取的固定代理配置，Fader 会保留该配置并添加网站直连规则。Chrome 跟随系统代理时，不一定能向扩展提供底层代理地址和端口，需要手动填写。
- Fader 管理浏览器代理设置，不提供代理节点或代理协议内核，也不支持导入订阅链接。
- 仅通过 TUN、虚拟网卡或系统 VPN 接管流量的软件，可能没有可用的本地代理端口；Fader 无法绕过这些系统层面的接管。
- 网站直连和全局直连都作用于当前 Chrome 配置，不修改系统代理，也不直接影响其他软件。

## 安装试用

1. 打开 Chrome 的 `chrome://extensions`。
2. 开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本项目目录（包含 manifest.json 的目录）。
4. 在工具栏的扩展菜单中固定 Fader，打开普通网站后点击它。

正式面向普通用户分发时，应发布到 Chrome 应用商店，免去开发者模式步骤。

## 首次连接

默认使用 Chrome 侧栏（Chrome 116+）。点击扩展图标展开，在设置的「显示模式」中可切换为弹窗；偏好保存在本地。弹窗中选择侧栏会立即打开侧栏并关闭弹窗；选择弹窗后，扩展图标改为打开弹窗，已打开的侧栏可手动关闭。侧栏左右位置由 Chrome 的用户设置决定。侧栏会跟随所在窗口的当前标签页更新网址。

如果 Chrome 返回可读取的固定代理配置，直接保留原配置并添加域名例外。否则默认使用 127.0.0.1:7890，无首次设置弹窗；7890 是默认值，不是探测结果。可在右上角设置中修改 HTTP 或混合端口，保存后优先使用该本地端口并立即更新现有规则。全部恢复后仍保留端口偏好。这里没有扫描本地端口，也没有声称连接已验证。

## 行为与边界

- 主界面小白球向下拖到 fade/allow 区域松手开启全局直连（direct），即当前 Chrome 配置内所有网站直连。向上拖回或连续双击小球关闭；键盘聚焦后可按回车或空格切换。
- 全局直连保留原网站规则和端口，关闭后恢复网站分流；没有网站规则时释放代理设置，恢复底层配置。状态保存在本地，重启后保留。普通点击 fade/allow 仍只切换当前域名。
- 全局直连期间，设置中可以修改端口或清除网站规则，不会关闭全局直连。切换时刷新当前网页，其他已打开网页如需立即重建连接请手动刷新。此开关不能绕过系统 TUN/VPN。

- 使用 fixed_servers + bypassList；精确域名匹配，不影响相似域名或其他子域名。同域所有路径和端口均生效，不能只针对 HTTPS 路径。
- 其他域名的资源继续遵循代理配置。规则对浏览器配置整体生效，不是仅当前标签页。
- 保留读取到的固定代理及已有 bypassList。移除最后一个域名或点击全部恢复时，调用 clear 释放扩展代理设置，让 Chrome 恢复底层设置。禁用或卸载扩展也会释放设置。
- 接管期间不会自动追踪系统代理开关或端口变化。关闭代理软件、更改端口前，请全部恢复；之后可重新添加网站。代理不可达时不会主动降级为全部直连。
- TUN/VPN 仍可能接管直连流量。显示「已设置直连」仅表示配置状态，不表示端到端验证。
- 不在无痕窗口提供切换操作，但 Chrome 的无痕代理可能继承普通窗口设置。
- 管理策略或其他代理扩展占用时显示错误，不强行接管。
- 申请 proxy、storage、tabs、sidePanel、scripting 及 HTTP/HTTPS 网页权限；tabs 用于常驻侧栏跟随标签页读取网址，scripting 与网页权限用于切换成功后向当前网页注入约 2 秒的代码和粒子覆盖动画。不读取网页正文，不向外传输网页数据。
- fade/allow 和全局直连切换成功后，在当前网页播放覆盖动画，结束后移除并刷新；动画期间如果已导航到其他网址，不刷新新页面。Chrome 内置页面、应用商店等受限页面无法注入时保留插件内过场。系统减少动态效果开启时跳过动画。

## 验证

运行 `npm test`。手动验收：启动提供本地 HTTP 或混合端口的代理软件，开启系统代理并关闭 TUN/VPN 接管，在 Fader 中确认端口与客户端一致；通过客户端连接日志对比添加规则前后，检查另一个域名仍通过代理、刷新/浏览器重启后规则保留、全部恢复及禁用扩展后跟随系统。分别检查错误端口、其他代理扩展冲突、TUN 和无痕情况。测试中不要只依赖页面显示的 IP 判断分流结果。
